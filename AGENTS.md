# Agent instructions

## Product and design decisions

Read [`product-guidelines.md`](product-guidelines.md) before building a feature or making a design decision (copy, layout, dates and status, color and icons). Follow it. If a change would conflict with a guideline, ask Dave first and update the file once he decides.

## Figma reviews

Only create or update screenshots, snapshots, pages or variables in Figma when Dave explicitly asks for it. Never do it as a routine part of a PR or task, even when a change touches the UI or adds states to [`test-cases.md`](test-cases.md). Saving local screenshots to files for a PR is fine; only pushing them to Figma needs his request.

When Dave asks to put screens in Figma for review, follow the [`figma-review`](.cursor/skills/figma-review/SKILL.md) skill. [`test-cases.md`](test-cases.md) lists the states to capture and the page naming rule.

## Project docs

`PLAN.md` holds the product rules and architecture, and `README.md` explains how to run the project.
